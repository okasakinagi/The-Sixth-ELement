# 前端总体结构说明（Frontend Overview）

## 一、页面整体结构概览

前端整体由 **8 个主页面** 组成，覆盖用户从登录、填写问卷到管理问卷与积分的完整流程：

1. 登录（Login）
2. 注册（Register）
3. 任务中心（Task Center）
4. 问卷管理（Survey Management）
5. 问卷制作（Survey Builder）
6. 问卷填写（Survey Filling）
7. 帮助中心（Help Center）
8. 个人资料（Profile）
9. 积分记录（Points History）

其中：

- **登录 / 注册** 是用户进入系统的起始页面；
- **任务中心、问卷管理、帮助中心、个人资料、积分记录** 构成核心功能菜单；
- **问卷制作、问卷填写** 为流程型页面，不作为常驻菜单项。

---

## 二、页面层级与导航结构

### 1. 页面访问路径逻辑

整体结构可概括为：

**登录 / 注册 → 主功能页面 → 流程型页面**

即：

- 用户完成登录或注册后进入系统主区域；
- 通过主菜单访问核心功能页面；
- 在特定操作中（如创建或填写问卷）进入问卷制作 / 问卷填写页面，完成后返回主页面。

该结构可理解为 **1 → 5 → 2** 的层级关系。

---

### 2. 主菜单结构（5 个）

主菜单包含以下 **5 个页面**：

- 任务中心
- 问卷管理
- 帮助中心
- 个人资料
- 积分记录

说明：

- 主菜单在用户登录后常驻显示；
- 问卷制作、问卷填写不出现在主菜单中，仅通过业务流程进入。

---

## 三、核心页面说明

### 1. 任务中心（Task Center）

**页面定位**

- 填写者的主要入口页面；
- 用于浏览、筛选和选择可填写的问卷。

**主要功能**

- 展示推荐系统返回的问卷列表；
- 显示问卷基础信息（标题、AI 难度等级、可获得积分等）。

**快捷入口设计**

- 页面中提供 **个人资料** 与 **积分记录** 的快捷入口；
- 表现形式为可移动的小块（floating widget）；
- 小块包含两个按钮：
  - 💰 积分入口（钱袋子图标）
  - 👤 个人资料入口（人物图标）

---

### 2. 问卷管理（Survey Management）

**页面定位**

- Sender（发问卷用户）的核心管理页面；
- 用于管理自己创建和发布的问卷。

**主要功能**

- 查看已发布 / 进行中 / 已完成的问卷；
- 查看问卷填写进度与状态；
- 进入问卷制作页面进行新建或编辑。
- 问卷列表按状态区分按钮：
  - 草稿问卷：显示“编辑问卷”，进入原草稿编辑；
  - 已发布/已结束问卷：显示“查看问卷”，进入查看并可编辑；保存时将另存为新问卷，不覆盖原问卷。

**快捷入口设计**

- 与任务中心保持一致；
- 同样提供可移动的小块，直达：
  - 积分记录
  - 个人资料

---

### 3. 问卷制作（Survey Builder）

**页面定位**

- 流程型页面；
- 用于创建和编辑问卷内容。

**页面特征**

- 能从任务中心、问卷管理页面进入；
- 不在主菜单中展示；
- 支持题目创建、编辑、顺序调整等操作；
- 完成后返回问卷管理页面。

---

### 4. 问卷填写（Survey Filling）

**页面定位**

- 流程型页面；
- 用户实际填写问卷的页面。

**页面特征**

- 仅能从任务中心进入；
- 填写过程中不显示主菜单，减少干扰；
- 提交完成后返回任务中心或结果提示页。

---

### 5. 帮助中心（Help Center）

**页面定位**

- 提供平台使用说明与常见问题解答。

**页面特征**

- 属于主菜单页面；
- 每个模块支持「有帮助 / 无帮助」反馈；
- 用户提交反馈后不可重复点击。

---

### 6. 个人资料（Profile）

**页面定位**

- 用户个人信息维护页面；
- 推荐系统的重要数据来源。

**主要功能**

- 编辑基础信息（性别、年级、专业等）；
- 编辑兴趣偏好；
- 展示资料完善度。

---

### 7. 积分记录（Points History）

**页面定位**

- 积分系统的可视化页面。

**主要功能**

- 展示积分获取与消耗记录；
- 区分填写问卷、发布问卷、平台奖励等来源。

---

## 四、GlobalFloatingMenu 悬浮控件说明

`src/components/GlobalFloatingMenu.vue` — 全局可拖动悬浮菜单

### 功能

- 显示当前登录用户的 **积分余额**（实时从 `/api/v1/users/me` 获取，每 30 秒刷新一次）
- 显示用户 **昵称首字母** 圆形头像，点击跳转个人资料页
- 可在屏幕任意位置拖拽，位置持久化存储到 `localStorage('floating_menu_position')`

### 头像逻辑

头像显示昵称首字母（大写）：
1. **初始值**：从 `localStorage('user_nickname')` 读取（登录时写入）
2. **动态更新**：每次 `fetchUserPoints()` 成功后，从 API 响应中同步 `data.nickname`，同时更新 `localStorage`
3. **页面可见性恢复**：`syncAuthState()` 会重新读取 `localStorage` 中的昵称

## 五、用户状态（currentStatus）存储方案

### 存储位置

状态存储在后端数据库 `UserProfile.current_status` 字段，通过 PATCH `/api/v1/profile/me` 接口读写。

### 字符串格式

```
主状态|补充描述|时间戳(毫秒)
```

示例：
- `😊 心情不错||1740000000000`（无描述，带时间戳）
- `赶ddl|还有2小时|1740000000000`（有描述，带时间戳）

各段含义：

| 段 | 内容 | 说明 |
|---|---|---|
| `parts[0]` | 主状态文本 | 必填，来自预设状态选项 |
| `parts[1]` | 补充描述 | 可为空字符串 |
| `parts[2]` | 设置时间戳（`Date.now()`） | 毫秒级 Unix 时间戳 |

### 24 小时自动过期

在 `UserProfileView.vue` 的 `loadProfile()` 中：

```js
const parts = userData.value.currentStatus.split('|')
const timestamp = parts[2] ? parseInt(parts[2]) : null
if (timestamp && Date.now() - timestamp > 24 * 60 * 60 * 1000) {
  // 调用后端清除，并更新前端状态
  updateUserProfile({ current_status: '' })
}
```

### 多端兼容性

时间戳存在 **后端**，不依赖 `localStorage`，因此用户在任意设备登录均可正确判断状态是否过期。

### 前端显示（`currentStatusDisplay` computed）

只取 `parts[0]`（主状态）和 `parts[1]`（描述）拼接显示，时间戳不展示给用户。

## 六、设计一致性约定（前端实现参考）

- **任务中心 / 问卷管理**

  - 使用统一的快捷入口组件；
  - 样式与交互保持一致，避免重复实现。

- **流程型页面（问卷制作 / 问卷填写）**
  - 不显示主菜单；
  - 通过完成或返回操作回到主页面。
