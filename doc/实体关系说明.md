# 数据库 ER 文档（当前实现版）

本文档用实体关系视角描述当前数据库结构。实体名与字段以 [core/models.py](core/models.py) 为准。

## 1. 总体关系

当前实现的主链路是：

1. `AppUser` 创建 `Survey`
2. `Survey` 绑定 `Questionnaire`，`Questionnaire` 下挂 `Question`
3. `Question` 下挂 `QuestionOption`
4. 用户填写问卷生成 `Response`，并写入逐题 `Answer`
5. 提交成功后写入 `PointsLog`
6. 违规或异常由 `Report` 记录，管理员操作写入 `AuditLog`
7. 推荐与标签体系由 `Tag`、`SurveyTag`、`UserTag`、`UserTagWeight`、`IDVector`、`SurveyUserSimilarity` 支撑
8. 任务、首页、风控与埋点由 `TaskCompletion`、`HomeModuleConfig`、`RiskEvent`、`UserBehaviorLog` 支撑

## 2. 核心实体

### 2.1 AppUser

平台用户基础实体。

字段要点：

- `nickname`
- `email`
- `credit_score`
- `points`
- `activity_points`
- `level`
- `title`
- `status`
- `created_at` / `updated_at` / `last_active_at`

关系：

- 1:N `Survey.owner`
- 1:1 `AuthCredential.user`
- 1:N `AuthToken.user`
- 1:N `Response.user`
- 1:N `PointsLog.user`
- 1:N `Report.reporter`
- 1:N `Report.handled_by`
- 1:N `AuditLog.operator`
- 1:N `Message.user`
- 1:N `Message.sender`
- 1:N `Team.owner`
- 1:N `TeamMember.user`
- 1:N `TeamInvitation.inviter`
- 1:N `TeamInvitation.invitee`
- 1:N `UserTag.user`
- 1:N `UserTagWeight.user`
- 1:N `SurveyUserSimilarity.user`
- 1:N `DailyRecommendation.user`
- 1:N `TaskCompletion.user`
- 1:N `RiskEvent.user`
- 1:N `UserBehaviorLog.user`

### 2.2 AuthCredential / AuthToken / PasswordResetCode

认证与密码相关实体。

- `AuthCredential`：用户密码哈希
- `AuthToken`：Bearer Token 记录
- `PasswordResetCode`：注册和重置密码验证码

### 2.3 Role / UserRole

权限角色实体。

- `Role`：角色定义
- `UserRole`：用户与角色的多对多关系

### 2.4 Survey / Questionnaire / Question / QuestionOption

问卷主流程实体。

- `Survey`：问卷任务主表
- `Questionnaire`：问卷版本
- `Question`：题目
- `QuestionOption`：题目选项

关系：

- 1:N `Survey.Questionnaire`
- 1:N `Questionnaire.Question`
- 1:N `Question.QuestionOption`
- `Survey.active_questionnaire` 指向当前生效版本

### 2.5 Response / Answer

答卷实体。

- `Response`：一次填写记录
- `Answer`：逐题答案

关系：

- `Response.survey` -> `Survey`
- `Response.questionnaire` -> `Questionnaire`
- `Response.user` -> `AppUser`
- `Answer.response` -> `Response`
- `Answer.question` -> `Question`

说明：当前主流程是提交后立即发放积分，`Response.status` 写入 `submitted`。

### 2.6 PointsLog

积分账本。

字段要点：

- `points_type`
- `delta`
- `reason`
- `ref_type`
- `ref_id`
- `created_at`

业务约束：所有积分变化都应落 `PointsLog`，包括发布扣费、填写奖励、任务奖励、管理调整等。

### 2.7 Report / AuditLog

异常处理与审计实体。

- `Report`：举报记录，包含 `target_type`、`target_id`、`reason`、`status`、`handled_by`
- `AuditLog`：管理员操作留痕

### 2.8 Message

站内消息实体。

当前支持：

- 系统消息
- 队伍邀请
- 积分赠送

核心字段：

- `user`
- `sender`
- `type`
- `message_type`
- `title`
- `content`
- `status`
- `ref_type`
- `ref_id`
- `points_amount`
- `is_accepted`

### 2.9 Team / TeamMember / TeamInvitation

组队协作实体。

- `Team`：队伍
- `TeamMember`：队伍成员
- `TeamInvitation`：邀请追踪

关键约束：

- 同一队伍同一用户只有一条成员记录
- 同一队伍对同一被邀请人只能有一条 `pending` 邀请

## 3. 标签与推荐实体

### 3.1 Tag

统一标签定义实体。

标签类型包括：

- `survey_type`
- `interest`
- `school`
- `gender`
- `age`
- `grade`
- `college`
- `major`
- `mbti`
- `organization`
- `consumption`
- `career`
- `skill`
- `status`

### 3.2 SurveyTag / UserTag / UserTagWeight

- `SurveyTag`：问卷与标签关联
- `UserTag`：用户与标签关联
- `UserTagWeight`：用户标签权重

推荐系统主要依赖 `UserTagWeight`，`UserTag` 作为回退。

### 3.3 IDVector / SurveyUserSimilarity / DailyRecommendation

- `IDVector`：对象向量缓存
- `SurveyUserSimilarity`：问卷与用户相似度缓存
- `DailyRecommendation`：每日推荐缓存

---

## 4. 任务、首页与风控

### 4.1 TaskCompletion

周期任务进度记录。

### 4.2 HomeModuleConfig

首页模块配置。

### 4.3 RiskEvent

风控事件记录。

当前事件类型：

- `short_duration`
- `suspicious_behavior`
- `abnormal_survey`
- `multiple_submissions`
- `ip_anomaly`

### 4.4 UserBehaviorLog

用户行为埋点。

当前场景包括：

- `task_list`
- `task_refresh`
- `daily_recommend`
- `home_feed`
- `home_trending`
- `fill_entry`

---

## 5. 当前不再使用的旧命名

以下旧名称不再作为当前实体的正式命名：

- `Notification` -> 以 `Message` 取代
- `UserProfile` -> 以 `AppUser` + 画像相关标签/字段承载
- `SurveyDraft` -> 草稿逻辑合并到 `Survey` / `Questionnaire`

---

## 6. 设计结论

当前数据库结构的特点是：

- 核心业务集中在 `Survey`、`Questionnaire`、`Response`、`PointsLog`
- 推荐系统通过标签、权重和向量缓存实现
- 团队与消息系统已经独立成实体
- 任务、首页和风控具备独立的支撑表

这份 ER 文档应与 [doc/数据模型字典.md](doc/数据模型字典.md) 保持一致；前者偏关系视角，后者偏字段视角。
