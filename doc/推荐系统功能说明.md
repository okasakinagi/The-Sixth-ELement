**1. 功能目标**
1. 把 `user` 标签和 `survey` 标签转成向量（embedding）。
2. 计算当前用户与候选问卷的语义匹配分。
3. 按分数排序，任务大厅优先展示最相关问卷。
4. 点击“换一批”时，返回下一批不重复问卷。

**2. 代码落点（主链路）**
1. 向量与打分核心：`core/managers/similarity_manager.py`
2. 业务服务封装：`core/services/similarity_service.py`
3. 任务大厅接入：`task_hall/service/task_hall_service.py`
4. 用户改标签后刷新向量：`core/views.py`
5. 前端“换一批”去重：`frontend/sixth_element/src/views/TaskHallView.vue`
6. embedding 配置来源：`deploy/ai_config.json`（环境变量优先）

**3. 推荐流程（端到端）**
1. 前端打开任务大厅，调用 `GET /api/v1/task-hall/tasks?page_size=15&sort=recommend`。
2. 后端先按业务规则筛候选问卷（进行中、非自己发布、未填写过）。
3. 对候选问卷做个性化打分（embedding 语义匹配）。
4. 按分数降序，返回前 15 条。
5. 前端保存这批问卷 ID 到 `seenTaskIds`。
6. 点击“换一批”时，前端把 `seenTaskIds` 传给 `POST /api/v1/task-hall/batch/refresh`。
7. 后端排除这些 ID 后，继续按同样打分逻辑返回下一批。

**4. 向量生成逻辑**
1. 优先读取环境变量：
`EMBEDDING_API_KEY / EMBEDDING_BASE_URL / EMBEDDING_MODEL`。
2. 若环境变量不完整，回退读取 `deploy/ai_config.json`。
3. 若 `base_url` 写成 `.../chat/completions`，会自动归一化为 `.../embeddings`。
4. 实际请求是 OpenAI 兼容格式：
`POST <base_url>`，body 为 `{"model":"...","input":"..."}`。
5. 从响应里读取 `data[0].embedding`。
6. 若外部 embedding 请求失败，会降级到 deterministic 本地向量（保证功能不断）。

**5. 标签与向量缓存策略**
1. `tag` 级向量会缓存到 `IDVector`（`ref_type='tag'`），避免反复编码同一标签。
2. `user/survey` 也能存向量，但推荐主逻辑现在是按“标签向量组合”算分。
3. 用户标签更新时，会触发用户向量刷新（减少推荐延迟）。

**6. 核心打分公式（会议重点）**
对每份问卷 `survey`：
1. 取该问卷所有标签 `S={s1,s2...}`。
2. 取当前用户标签 `U={u1,u2...}`，并带权重 `w(ui)`（来自 `UserTagWeight`，归一化到 0~1）。
3. 对每个问卷标签 `s`，计算它和所有用户标签的相似度，取最佳匹配：  
`best(s) = max_i( cosine(emb(s), emb(ui)) * w(ui) )`
4. 问卷总分为所有 `best(s)` 的平均值：  
`score(survey) = mean( best(s) for s in S )`
5. 按 `score` 降序排序返回。

这保证了“每个 survey tag 都会去找 user tag 的最佳语义对齐”。

**7. 冷启动与异常降级**
1. 用户没标签：返回低分并给“标签不足”原因。
2. 问卷没标签：该问卷记低分（“问卷暂无标签”）。
3. embedding 服务不可用：自动回退本地向量，不阻塞页面。

**8. 任务大厅展示效果**
1. `match_level` 由匹配分映射（high / medium / low）。
2. `match_reason` 会返回类似“问卷标签A与你的标签B匹配”。
3. 前端卡片展示该理由，不再只是“按奖励/难度伪匹配”。

**9. 当前配置与上线注意点**
1. embedding使用 `Qwen/Qwen3-Embedding-4B`，建议：
`base_url=https://api.siliconflow.com/v1/embeddings`。
2. 建议生产用环境变量，不把真实 key 放仓库。
3. 推荐质量强依赖标签质量：标签覆盖率、命名一致性、噪声控制很关键。

**10. 总结**
这版推荐从“规则排序”升级成“标签语义检索排序”：  
先筛业务可见候选，再用 embedding 计算用户标签与问卷标签的语义贴合度，按分数推送 top15，并通过 `seenTaskIds` 保证“换一批”拿到下一组不重复结果。
