## 4. 当前推荐总公式

### 4.1 统一定义
1. 兴趣匹配分：S_interest，范围0~100。
2. 效率适配分：S_efficiency，范围0~100。
3. 行为惩罚因子：P_behavior，范围(0,1]。

### 4.2 最终分
S_final = S_interest * (S_efficiency / 100) * P_behavior

### 4.3 兼容输出分
为了兼容既有前端阈值（high/medium/low），接口继续返回：
score = clamp(S_final / 100, 0, 1)

说明：
1. 前端原阈值逻辑无需改动。
2. 新增分项字段仅作为扩展信息，不破坏现有渲染。

## 5. 阶段2：兴趣匹配分（标签硬匹配 + 语义补充）

### 5.1 公式
S_interest = 0.6 * S_tag + 0.4 * S_semantic

其中：
1. S_tag：标签硬匹配分（0~100）。
2. S_semantic：语义分（cosine裁剪到0~1后乘100）。

### 5.2 标签硬匹配分 S_tag
1. 用户标签来源优先级：
	- UserTagWeight（主）
	- UserTag（回退，默认权重1.0）
2. 对每个用户标签，在问卷标签集合中取最强匹配：
	- 完全同名：1.0
	- 关联映射命中：relation_score
	- 否则：0.0
3. 用用户正向权重预算归一化到0~100。

### 5.3 兴趣关联映射
1. 在 SimilarityManager 内置 _INTEREST_RELATION_MAP。
2. 目标是补足“语义近、标签不同名”的场景（如 Python 与 编程竞赛）。
3. 映射是可维护常量，不依赖额外模型服务。

## 6. 阶段3：效率适配分

### 6.1 公式
S_efficiency = 0.4 * S_time + 0.3 * S_num + 0.2 * S_type + 0.1 * S_pro

然后再乘疲劳惩罚：
S_efficiency = S_efficiency * (1 / (1 + 0.2 * domain_fill_count_24h))

### 6.2 用户效率画像
从历史已提交 Response 计算：
1. tolerate_time：用户单题耐受时长（历史均值）。
2. tolerate_num：用户耐受题量（P90分位）。
3. type_ratio：用户历史题型分布偏好。
4. domain_proficiency：按标签领域估计熟练度（基于单题时长倒数归一化）。

### 6.3 问卷效率画像
从问卷题目结构预估：
1. pre_time：单题预计时长。
2. question_num：总题量。
3. type_ratio：题型占比。
4. domain_level：领域门槛（结合难度与标签关键词规则）。

### 6.4 题型时间基准
1. single: 5秒
2. multi: 8秒
3. scale: 6秒
4. open/text/multi-text: 30秒

## 7. 阶段4：前置硬过滤与行为惩罚

### 7.1 前置硬过滤（先过滤后打分）
过滤条件：
1. 已提交过该问卷（filled_survey_ids）。
2. 命中近30天硬负向标签（权重接近0）。
3. 命中24小时“高退出”标签（同标签24小时退出次数 > 2）。

### 7.2 行为惩罚因子
P_behavior 初始值为 1.0，然后按条件乘法衰减：
1. 问卷标签命中 quit_tags：*0.5
2. 问卷标签命中 slow_tags：*0.7

最终：
P_behavior = 1.0 * quit_penalty * slow_penalty

---

## 8. 阶段5：行为闭环（必须长期生效）

### 8.1 提交成功正反馈
在 surveyfill 提交成功后：
1. 找到问卷所有 SurveyTag。
2. 对用户对应 UserTagWeight 加 1.5（封顶5.0）。
3. 失效用户向量缓存，确保下一次推荐立即生效。

### 8.2 画像修改同步权重
在 personal_homepage 画像更新时：
1. 单值标签更新：同步写 UserTag 与 UserTagWeight（2.0）。
2. 多值标签更新：同步写 UserTag 与 UserTagWeight（2.0）。
3. 删除画像时：同步清理 UserTagWeight。
4. 每次修改后失效用户向量缓存。

## 9. 阶段6：时序动态衰减

### 9.1 公式
decayed_weight = base_weight * exp(-lambda * day_diff)

### 9.2 当前参数
1. lambda = 0.05
2. 在用户权重聚合入口统一生效（无需改数据库结构）。

### 9.3 作用
1. 近期行为影响更大。
2. 历史陈旧兴趣自动降权。

---

## 10. 阶段7：多样性弹性排序（80/20）

### 10.1 规则
在一个返回窗口中：
1. 前80%：保持主排序结果。
2. 后20%：从探索池补位。

### 10.2 探索池准入条件
1. interest_score >= 60
2. efficiency_score >= 80
3. 不在当前窗口

### 10.3 探索池排序
1. 按 filled 数量升序（低热度优先）。
2. 同热度下按 score 降序。

### 10.4 目标
1. 保持主推荐精准度。
2. 避免信息茧房。
3. 为低热度但高适配问卷提供曝光。

## 13. 调参建议
建议先小步调参并观察7天：
1. 兴趣融合权重：0.6/0.4 可按完成率微调到 0.7/0.3。
2. 效率分权重：0.4/0.3/0.2/0.1 可按业务偏好调整。
3. 惩罚因子：0.5、0.7 不宜同时过低，避免过度压制。
4. 衰减系数 lambda：默认0.05，可在0.03~0.08区间测试。
5. 探索比例：80/20 可改为 85/15 或 90/10。
