# 数据库表结构（当前实现版）

本文档只描述当前代码中的真实模型。数据库字段、约束和索引以 [core/models.py](core/models.py) 与迁移文件为准。

说明：

- 其他应用（`survey_management`、`surveyfill`、`task_hall`、`points_record`、`personal_homepage`、`team_messaging`、`admin_backend`、`user_profile_extractor`）当前主要复用 `core/models.py` 中的表，不单独定义新的业务表。
- Django 默认表名以 `core_` 前缀为主，实际库表名由迁移生成。
- 本文不包含历史方案、已废弃字段或规划中的表结构。

## 1. 用户与认证

### AppUser

用户基础信息与业务快照。

- `nickname`：昵称
- `email`：邮箱，唯一
- `credit_score`：信用分，默认 `0`
- `points`：可交易积分，默认 `0`
- `activity_points`：活跃度积分，默认 `0`
- `level`：等级，默认 `1`
- `title`：称号，默认 `新手探索者`
- `status`：用户状态，默认 `normal`
- `created_at` / `updated_at` / `last_active_at`

### AuthCredential

用户密码凭据。

- `user`：一对一关联 `AppUser`
- `password_hash`：密码哈希
- `created_at` / `updated_at`

### AuthToken

Bearer Token 记录。

- `user`：关联 `AppUser`
- `token`：唯一令牌，带索引
- `expires_at`：过期时间，可空
- `created_at`

### PasswordResetCode

邮件验证码表，复用注册验证和密码重置。

- `email`：邮箱，带索引
- `code_hash`：验证码 SHA-256 哈希
- `purpose`：`register` / `reset`
- `expires_at`：过期时间
- `is_used`：是否已使用
- `attempt_count`：错误尝试次数
- `created_at`

## 2. 角色

### Role

角色定义。

- `name`：角色名
- `description`：描述，可空

### UserRole

用户与角色的多对多关系。

- `user`：关联 `AppUser`
- `role`：关联 `Role`
- `created_at`

约束：同一用户和同一角色只能有一条记录。

## 3. 问卷主流程

### Survey

问卷任务主表。

- `owner`：发布者，关联 `AppUser`
- `title`：标题
- `description`：说明/副标题，可空
- `estimated_minutes`：预计耗时，可空
- `difficulty`：难度，默认 `3`
- `reward_points`：单份填写奖励积分，默认 `0`
- `publish_cost_points`：发布预算/扣费总额，默认 `0`
- `deadline`：截止时间，可空
- `target`：目标份数，默认 `1`
- `completed`：已完成份数，默认 `0`
- `status`：状态，默认 `draft`
- `ai_generated`：是否 AI 生成
- `active_questionnaire`：当前生效问卷版本，可空
- `created_at` / `updated_at`

说明：底层字段是字符串状态；业务层会把 `draft`、`published`、`paused`、`ended` 作为主流程状态使用，兼容逻辑还会见到 `active`、`live`、`closed`、`expired`、`rejected`。

### Questionnaire

问卷版本表。

- `survey`：所属 `Survey`
- `version`：版本号，默认 `1`
- `status`：状态，默认 `draft`
- `title`：版本标题
- `created_at` / `updated_at`

### Question

题目表。

- `questionnaire`：所属 `Questionnaire`
- `order_no`：题目顺序，默认 `1`
- `type`：题型
- `title`：题干
- `description`：题目说明，可空
- `is_required`：是否必填，默认 `True`
- `config_json`：题型配置，可空
- `logic_json`：跳题逻辑，可空
- `created_at` / `updated_at`

约束：同一问卷内 `questionnaire + order_no` 唯一。

### QuestionOption

题目选项表。

- `question`：所属 `Question`
- `order_no`：选项顺序，默认 `1`
- `label`：展示文本
- `value`：存储值
- `is_other`：是否“其他”选项
- `extra_config_json`：扩展配置，可空
- `created_at`

约束：同一题内 `question + order_no` 唯一。

### Response

一次答卷记录。

- `survey`：所属问卷
- `questionnaire`：答题时使用的版本
- `user`：填写用户
- `status`：状态，默认 `in_progress`
- `started_at`：开始时间，可空
- `submitted_at`：提交时间，可空
- `duration_seconds`：填写时长，可空
- `risk_flag`：是否风控命中，默认 `False`
- `evidence_url`：证据地址，可空
- `device_fingerprint`：设备指纹，可空
- `ip_hash`：IP 哈希，可空
- `created_at` / `updated_at`

说明：当前写入流程会在提交成功时创建 `Response`，状态写为 `submitted`，并补 `submitted_at`。

约束：同一用户对同一问卷只能有一条 `Response`。

### Answer

逐题答案表。

- `response`：所属 `Response`
- `question`：所属 `Question`
- `value_text`：文本答案，可空
- `value_json`：结构化答案，可空
- `created_at` / `updated_at`

约束：同一答卷同一题只能有一条答案。

## 4. 积分、举报、审计

### PointsLog

积分流水账本。

- `user`：所属用户
- `points_type`：积分类型
- `delta`：变动值，正负均可
- `reason`：原因说明
- `ref_type`：来源对象类型，可空
- `ref_id`：来源对象 ID，可空
- `created_at`

这是系统里唯一的积分账本表，发布、填写、任务、管理员调整等变更都应写入这里。

### Report

举报记录。

- `reporter`：举报人
- `target_type`：被举报对象类型
- `target_id`：被举报对象 ID
- `reason`：举报原因
- `detail`：补充说明，可空
- `status`：默认 `open`
- `handled_by`：处理人，可空
- `created_at` / `handled_at`

### AuditLog

管理员审计日志。

- `target_type`：被操作对象类型
- `target_id`：被操作对象 ID
- `action`：操作动作
- `operator`：操作人，可空
- `note`：备注，可空
- `created_at`

## 5. 站内消息与组队

### Message

站内消息表，兼容系统消息、队伍邀请和积分赠送。

- `user`：接收者
- `type`：历史兼容字段
- `title`：标题
- `content`：内容
- `status`：默认 `unread`
- `created_at` / `read_at`
- `sender`：发送者，可空
- `message_type`：消息类型，当前值包括 `system`、`team_invite`、`points_gift`
- `ref_type`：关联对象类型，可空
- `ref_id`：关联对象 ID，可空
- `points_amount`：赠送积分数，默认 `0`
- `is_accepted`：是否接受，默认 `False`

### Team

队伍表。

- `owner`：队长
- `title`：队伍名，可空
- `description`：描述，可空
- `max_members`：最大成员数，默认 `5`
- `status`：`active` / `closed`
- `created_at` / `updated_at` / `closed_at`

### TeamMember

队伍成员关系表。

- `team`：所属队伍
- `user`：成员用户
- `role`：`member` / `admin`
- `status`：`invited` / `joined` / `left` / `kicked`
- `joined_at` / `left_at`

约束：同一队伍同一用户只能有一条成员记录。

### TeamInvitation

队伍邀请追踪表。

- `team`：所属队伍
- `inviter`：邀请人
- `invitee`：被邀请人
- `status`：`pending` / `accepted` / `rejected` / `expired`
- `attempt_count`：邀请次数，默认 `1`
- `last_invited_at`：最后一次邀请时间
- `accepted_at` / `rejected_at`
- `created_at` / `updated_at`

约束：同一队伍对同一被邀请人最多保留一条 `pending` 邀请。

## 6. 标签与推荐

### Tag

标签定义表。

- `name`：标签名
- `type`：标签类型
- `created_at`

当前实现中的标签类型包括：

- `survey_type`
- `interest`
- `school`
- `gender`
- `age`
- `grade`
- `college`
- `major`
- `mbti`
- `organization`
- `consumption`
- `career`
- `skill`
- `status`

### SurveyTag

问卷与标签关联表。

- `survey`：问卷
- `tag`：标签
- `created_at`

约束：同一问卷同一标签只能关联一次。

### UserTag

用户与标签关联表。

- `user`：用户
- `tag`：标签
- `created_at`

约束：同一用户同一标签只能关联一次。

### UserTagWeight

用户标签权重表，供推荐系统使用。

- `user`：用户
- `tag`：标签
- `weight`：权重，默认 `0.0`
- `updated_at`

约束：同一用户同一标签只有一条权重记录。

### IDVector

向量缓存表。

- `ref_type`：引用类型，通常为 `user` 或 `survey`
- `ref_id`：引用对象 ID
- `vector`：二进制向量数据
- `created_at`

### SurveyUserSimilarity

问卷与用户相似度缓存表。

- `survey`：问卷
- `user`：用户
- `cosine`：余弦相似度
- `created_at`

约束：同一问卷和同一用户只能有一条记录。

### DailyRecommendation

每日推荐缓存表。

- `user`：用户
- `date`：日期
- `survey_ids`：推荐问卷 ID 列表，JSON
- `claimed_ids`：已领取奖励的问卷 ID 列表，JSON
- `created_at`

约束：同一用户同一天只有一条缓存。

## 7. 任务、首页与行为

### TaskCompletion

任务完成进度表。

- `user`：用户
- `task_code`：任务编码
- `period_key`：周期标识
- `progress`：当前进度，默认 `0`
- `completed`：是否完成，默认 `False`
- `claimed`：是否已领取奖励，默认 `False`
- `created_at` / `updated_at`

约束：同一用户、同一任务、同一周期只有一条记录。

### HomeModuleConfig

首页模块配置表。

- `module_key`：模块键，唯一
- `title`：模块标题
- `enabled`：是否启用
- `weight`：权重
- `item_limit`：模块条目上限
- `created_at` / `updated_at`

### RiskEvent

风控事件记录。

- `user`：关联用户，可空
- `survey`：关联问卷，可空
- `event_type`：事件类型
- `severity`：`low` / `medium` / `high`
- `detail`：详情 JSON，可空
- `created_at`

当前事件类型包括：

- `short_duration`
- `suspicious_behavior`
- `abnormal_survey`
- `multiple_submissions`
- `ip_anomaly`

### UserBehaviorLog

用户行为埋点表。

- `user`：用户，可空
- `survey`：问卷，可空
- `event_type`：`impression` / `click` / `refresh` / `dismiss`
- `scene`：`task_list` / `task_refresh` / `daily_recommend` / `home_feed` / `home_trending` / `fill_entry`
- `meta_json`：补充信息，默认 `{}`
- `created_at`

## 8. 当前实现中的关键关系

- `AppUser` 是多数业务表的根用户实体。
- `Survey` 通过 `active_questionnaire` 指向当前生效版本。
- `Questionnaire`、`Question`、`QuestionOption` 组成问卷结构。
- `Response` 与 `Answer` 记录一次填写与逐题答案。
- `PointsLog` 是唯一的积分账本。
- `Message`、`Team`、`TeamMember`、`TeamInvitation` 支撑组队与消息功能。
- `Tag`、`SurveyTag`、`UserTag`、`UserTagWeight`、`IDVector`、`SurveyUserSimilarity` 支撑推荐系统。
- `TaskCompletion`、`HomeModuleConfig`、`RiskEvent`、`UserBehaviorLog` 支撑任务、首页和风控埋点。

## 9. 不存在的旧表

当前实现中不再使用以下独立表作为真实存储目标：

- `UserProfile`
- `SurveyDraft`
- `Notification`
- 任何单独的 `points_record` 专属账本表

如需查看接口层的兼容命名，请以 [doc/api/](doc/api/) 下的当前专题文档为准。
